## Goal

Create the persistent Gesso/Lienzo domain and base CLI without changing the existing mockup flow or agent instructions.

This phase establishes `lienzos/` as the storage location and creates the minimum deterministic backend needed for later confirmation, linking, and agent skill work.

## Scope

Implement:

- New backend module `lib/gesso-manager.js`.
- New CLI group `gsd-canva gesso`.
- Commands:
  - `gsd-canva gesso create --name <name> --methodology <methodology> --language <language> [--json]`
  - `gsd-canva gesso status --id <ID> [--json]`
  - `gsd-canva gesso list [--json]`
  - `gsd-canva gesso append-turn --id <ID> --role <role> --content <content> [--tags <tags>] [--json]`
  - `gsd-canva gesso update-notes --id <ID> --field <field> --value <value> [--json]`
- Persistent structure:

```text
lienzos/
└── lienzo_001_<slug>/
    ├── lienzo.json
    ├── gesso.md
    └── sesion.json
```

- Sequential three-digit lienzo IDs independent from `canva-plans/`.
- Atomic JSON writes.
- Lock usage through `.gsd-canva/.lock`.
- Shared slug sanitization equivalent to existing plan folder naming.
- Human and JSON output consistent with existing CLI patterns.

Do not implement yet:

- `gesso write`.
- `gesso confirm`.
- Hashing.
- Link to `canva-plans/`.
- Agent skill aliases.
- Installer or doctor changes.
- Changes to `/canva-mockup`.

## Validation Rules

- `--name` is required for `create`.
- Supported methodology values:
  - `socratic`
  - `creative_brief`
  - `jobs_to_be_done`
  - `design_thinking`
  - `5w1h`
- Supported language values:
  - `es`
  - `en`
  - `it`
- `append-turn` roles:
  - `user`
  - `assistant`
  - `system`
- `append-turn` and `update-notes` are allowed only when status is `en_blanco`.
- Unknown note fields are rejected.
- All mutating operations must update `timestamps.updated` and append history when appropriate.

---

## Errors

Use the v1.5 error contract:

- `GSDC_GESSO_NOT_FOUND` exit 31
- `GSDC_GESSO_INVALID_STATE` exit 32

Use existing JSON parse/permission style where appropriate, but do not incorrectly report plan errors for lienzo failures.

## Tests

Add `tests/gesso.test.js` and wire it into `tests/run.js`.

Required tests:

- `create` creates `lienzos/` and the three expected files.
- IDs are sequential and independent from existing `canva-plans/`.
- Folder names are sanitized.
- `lienzo.json` matches the initial contract.
- `sesion.json` matches the initial contract.
- `status` returns the expected lienzo.
- `list` returns created lienzos.
- `append-turn` records turns in order with timestamp, role, content, and tags.
- `update-notes` updates only allowed fields.
- Invalid methodology is rejected.
- Invalid language is rejected.
- Unknown lienzo ID returns `GSDC_GESSO_NOT_FOUND`.
- Non-editable status blocks `append-turn` and `update-notes` once manually fixture-set.
- CLI `--json` output is structured and not double-wrapped.
- Existing plan tests still pass.

Run:

```bash
npm test
```
