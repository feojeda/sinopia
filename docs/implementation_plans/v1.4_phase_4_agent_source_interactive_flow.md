## Goal

Update the neutral `canva-mockup` capability instructions so all adapters guide agents through the new structured question flow.

This phase changes agent-facing instructions, not backend state-machine behavior.

---

## Scope

Update:

- `templates/agent-source/canva-mockup/instructions.md`
- Generated/legacy templates only if the repo intentionally keeps source and legacy command templates in sync.
- Tests that inspect rendered Antigravity, Codex, and OpenCode artifacts.

Required instruction changes:

- Run `gsd-canva plan questions --id <ID> --json`.
- Use native interactive UI when available.
- Use structured textual fallback when native UI is unavailable.
- Save each answer with `gsd-canva plan answer`.
- Never write `decisions.json` directly.
- Ask/decline optional `assets` before final confirmation.
- Confirm only from the user's final response.
- Do not let agent-generated text trigger confirmation.
- Avoid using "confirmo" or "confirmado" in agent filler/status messages before final confirmation.
- For choice fields with `allowCustom: true`, textual fallback must say that the user may write a custom option.
- Use `reset-confirmation` for post-confirmation changes.
- Do not describe `.antigravity/commands/` as the Antigravity 2.0 primary surface.

Do not change:

- Adapter target paths.
- Manifest lifecycle.
- Backend state machine except for test-only helpers if needed.

---

## Agent-Specific Requirements

Antigravity 2.0:

- Render through `.agents/skills/canva-mockup/SKILL.md`.
- Mention native interactive questions generically.
- Do not hardcode `.antigravity/commands/` as the primary path.

Codex:

- Render through `.codex/commands/canva-mockup.md`.
- Textual fallback must be clear and one-turn-at-a-time when needed.

OpenCode:

- Render through `.opencode/commands/canva-mockup.md`.
- Keep OpenCode marked experimental unless official format has been verified.
