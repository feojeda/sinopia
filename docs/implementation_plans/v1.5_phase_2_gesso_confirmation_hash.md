## Goal

Turn `gesso.md` into an approved, immutable conceptual contract with hash verification.

This phase adds the Gesso yield gate but still does not connect Gesso to mockup plans or agent skills.

## Scope

Implement:

- `gsd-canva gesso write --id <ID> --file <path> [--json]`
- `gsd-canva gesso confirm --id <ID> [--by <name>] [--json]`
- `gsd-canva gesso verify --id <ID> [--json]`
- Canonical hash helper for `sha256-gesso-v1`.
- Required-section validation for `gesso.md`.
- State transition from `gesso:en_blanco` to `gesso:gesso_listo`.
- Read-only enforcement after confirmation.

Do not implement yet:

- Plan linking.
- Agent skill aliases.
- Installer/doctor changes.
- Automatic generation of `gesso.md` content by the CLI.

- `Nombre del lienzo`
- `Metodologia usada`
- `Resumen narrativo`
- `Intencion visual y tonal`
- `Audiencia y contexto de uso`
- `Mensaje central`
- `Estructura de layout propuesta`

- `Exploraciones descartadas`
- `Recomendaciones para Abbozzo`

## Hash Contract

`sha256-gesso-v1` should hash canonical `gesso.md` content:

- normalize to NFC;
- normalize line endings to `\n`;
- trim trailing whitespace at the end of the full document;
- hash UTF-8 bytes.

Store the hash in:

```json
{
  "confirmation": {
    "confirmed": true,
    "confirmedAt": "ISO-8601",
    "confirmedBy": "user",
    "source": "chat",
    "hashAlgorithm": "sha256-gesso-v1",
    "gessoHash": "<sha256>"
  }
}
```

Also set:

- `status`: `gesso_listo`
- `timestamps.approved`
- `timestamps.updated`
- history entry for confirmation

---

## Validation Rules

- `write` is allowed only in `en_blanco`.
- `write` rejects missing, empty, or invalid source files.
- `write` must not confirm the Gesso.
- `confirm` is allowed only in `en_blanco`.
- `confirm` requires a valid `gesso.md`.
- `verify` succeeds when the current `gesso.md` hash matches `lienzo.json`.
- `verify` fails if `gesso.md` changed after confirmation.
- `append-turn`, `update-notes`, and `write` must be blocked after `gesso_listo`.

## Errors

Use:

- `GSDC_GESSO_INVALID_STATE` exit 32
- `GSDC_GESSO_ARTIFACT_MISSING` exit 33
- `GSDC_GESSO_INVALID_ARTIFACT` exit 34
- `GSDC_GESSO_CHANGED_AFTER_CONFIRMATION` exit 35

---

## Tests

Required tests:

- `write` copies valid content into `gesso.md`.
- `write` rejects missing source file.
- `write` rejects empty source file.
- `write` rejects missing required sections.
- `confirm` rejects invalid or placeholder `gesso.md`.
- `confirm` writes confirmation metadata and transitions to `gesso_listo`.
- `verify` passes immediately after confirm.
- Mutating `gesso.md` after confirm makes `verify` fail with `GSDC_GESSO_CHANGED_AFTER_CONFIRMATION`.
- `write`, `append-turn`, and `update-notes` fail after confirm.
- CLI `--json` output is structured and not double-wrapped.
- Existing Phase 1 tests still pass.

Run:

```bash
npm test
```

## Acceptance Criteria

- A Gesso can be written, validated, confirmed, and verified.
- Confirmed Gesso cannot be silently changed.
- Existing plan lifecycle remains unchanged.
- `npm test` passes.
