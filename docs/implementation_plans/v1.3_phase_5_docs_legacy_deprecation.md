## Goal

Update public documentation and migration guidance so users understand the new adapter model and Antigravity 2.0 skill-based installation.

This phase should not introduce new runtime behavior except warnings or documentation-facing messages already implemented by prior phases.

---

## Scope

Update:

- `README.md`
- Installation examples.
- `doctor` examples.
- Architecture diagrams.
- Any active implementation docs that still claim `.antigravity/commands/` is the primary Antigravity 2.0 surface.
- Release/migration notes for legacy `.antigravity/commands/`.

Do not rewrite historical proposal documents unless they are explicitly active user-facing documentation.

---

## Documentation Model

Use this conceptual framing:

```text
Agent skills/commands are the operational frontend.
gsd-canva CLI is the deterministic backend.
canva-plans/ is the auditable state.
```

Document supported adapters:

| Agent | Output | Status |
|---|---|---|
| Antigravity 2.0 | `.agents/skills/<id>/SKILL.md` | Primary |
| Codex | `.codex/commands/<id>.md` | Supported |
| OpenCode | `.opencode/commands/<id>.md` | Supported or experimental, depending on Phase 3 result |
| Antigravity legacy | `.antigravity/commands/<id>.md` | Deprecated compatibility |

---

## Required README Updates

- Replace architecture references that present `.antigravity/commands/` as the native Antigravity 2.0 discovery path.
- Add examples:

```bash
gsd-canva init --agent antigravity
gsd-canva init --agent codex
gsd-canva init --agent opencode
gsd-canva init --agent all
gsd-canva doctor --agent antigravity
```

- Explain that Antigravity 2.0 uses workspace skills.
- Explain legacy support and deprecation path.
