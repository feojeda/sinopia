## Goal

Allow users to safely reopen confirmed decisions, prevent stale mockup reuse, and complete the v1/v2 hash migration behavior.

---

## Scope

Implement:

- `planManager.resetConfirmation(planId)`.
- CLI command:
  - `gsd-canva plan reset-confirmation --id <ID> [--json]`
- Full reset behavior:
  - clear confirmation fields and hash.
  - preserve required values.
  - clear optional values.
  - clear `optionalAnswered`.
  - return to `mockup:questions_pending` when allowed.
- Stale mockup handling:
  - rename `mockup.html` to `mockup.html.stale.<timestamp>`.
  - wrap rename in `try/catch`.
  - return `staleRenameFailed: true` and `staleRenameError` if rename fails.
  - continue state cleanup even if rename fails.
- `submitMockup()` stale guard:
  - reject `mockup.html` when its mtime predates `confirmation.confirmedAt`.
- Unknown hash version guard:
  - if stored hash version starts with `sha256-decisions-` but is not v1 or v2, fail with `GSDC_INVALID_STATE` and `reason: "unknown_hash_version"`.

---

## Tests

Add tests for:

- Reset clears confirmation/hash and preserves required values.
- Reset clears optional values and `optionalAnswered`.
- Reset returns plan to `mockup:questions_pending`.
- Reset is idempotent.
- Reset from disallowed final states fails with `GSDC_INVALID_STATE`.
- Stale mockup is renamed.
- Failed stale rename returns `staleRenameFailed: true` and does not leave the plan stuck.
- `resetConfirmation()` releases lock on errors.
- `submitMockup()` rejects stale `mockup.html`.
- Unknown hash version fails with `reason: "unknown_hash_version"`.
- Existing v1 confirmed plans still resolve/submit.
- v2 plans detect post-confirmation tampering.
- CLI JSON output is not double-wrapped.

Run:

```bash
npm test
```

---

## Acceptance Criteria

- Users can correct confirmed decisions through a safe CLI path.
- Stale mockups cannot be reused silently.
- Reset behavior is recoverable and idempotent.
- Hash compatibility is explicit and tested.
- Existing lifecycle behavior still passes.
