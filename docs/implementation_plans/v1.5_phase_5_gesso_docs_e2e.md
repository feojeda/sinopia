## End-to-End Scenario

The e2e verification should run in a temporary workspace and assert:

1. `gsd-canva init` prepares the workspace.
2. `gsd-canva gesso create --name "Cafe de Barrio" --methodology socratic --language es --json` creates `lienzos/lienzo_001_cafe-de-barrio/`.
3. `append-turn` and `update-notes` mutate `sesion.json` safely.
4. `gesso write` accepts a valid Gesso Markdown fixture.
5. `gesso confirm` transitions to `gesso_listo`.
6. `gesso verify` passes.
7. `gsd-canva plan create --name "Cafe de Barrio" --json` still works.
8. `gesso link-plan --id 001 --plan 001 --json` links both sides.
9. `gsd-canva plan questions --id 001 --json` still works normally.
10. Existing direct `/canva-mockup` backend path remains independent of Gesso.

- What Gesso is.
- When to use `/lienzo-en-blanco`.
- How Gesso differs from mockup.
- What files are produced.
- How the user approves the Gesso.
- How to continue to mockup.

Developer docs must explain:

- `lienzos/` structure.
- `lienzo.json` fields.
- `sesion.json` fields.
- `gesso.md` required sections.
- Status transitions.
- Hash behavior.
- Link behavior with `canva-plans/`.
- Compatibility guarantees.

Command docs must include:

- All `gesso` subcommands.
- Required options.
- JSON examples.
- Error codes.
- Typical flow.
