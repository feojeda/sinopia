# v1.4 Phase 1: Field Registry and Decisions Normalization

**Proposal**: `docs/PROPOSAL_v1.4_interactive_questions_agent_adapters.md`  
**Protocol**: `docs/implementation_plans/v1.4_execution_review_protocol.md`

**PR target**: default branch  
**Status**: Pending approval

---

## Goal

Create the shared field model and safe decisions normalization needed by interactive questions without changing the active agent instructions yet.

This phase prepares the backend state model while keeping existing mockup flow behavior compatible.

---

## Scope

Implement:

- `FIELD_REGISTRY` in `lib/plan-manager.js`.
- Derived `REQUIRED_FIELDS`, `OPTIONAL_FIELDS`, and `ALL_FIELDS`.
- `ensureQuestionFields(decisions)` for legacy decisions normalization.
- `plan create` initialization of `assets`, `optionalAnswered`, and full `confirmation` skeleton.
- Hash helper support for `sha256-decisions-v1` and `sha256-decisions-v2`.
- Replacement of hardcoded required-field arrays in existing confirmation/resolve/submit logic.

Do not implement yet:

- `plan questions`
- `plan answer`
- `plan reset-confirmation`
- Agent-source instruction changes
- New adapter behavior

---

## Required Decisions

Before implementation, decide the error-code strategy from the proposal:

- Option A: add `GSDC_PLAN_NOT_FOUND` (24) and `GSDC_PLAN_ARTIFACT_MISSING` (25).
- Option B: keep current plan-not-found/artifact error codes and remove those new codes from active v1.4 scope.

Record the decision in the PR description. Do not leave code and docs inconsistent.

---

## Tests

Add or update tests for:

- `FIELD_REGISTRY` contains the seven expected fields.
- Derived field lists are consistent.
- New plans include `assets`, `optionalAnswered`, and confirmation skeleton.
- Legacy decisions without new fields are normalized in mutating operations.
- `confirmDecisions()` writes `sha256-decisions-v2`.
- Existing v1 confirmed hash fixtures still verify with v1 field list.
- Hardcoded required field arrays are removed from `confirmDecisions()`, `resolveQuestions()`, and `submitMockup()`.

Run:

```bash
npm test
```

## Acceptance Criteria

- Existing tests pass.
- Existing command behavior remains compatible.

- Legacy plans still work.
- Hash v1/v2 behavior is covered.
- No agent instructions are changed in this phase.
